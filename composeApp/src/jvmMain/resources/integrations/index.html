For tools that share devices with Claude

Let your own app take a turn on the device

Claude sessions check in here before they touch a phone, watch or simulator. Your app can do the same. Ask for a device, wait in the same queue, use it, then give it back. Nobody fights over the screen.

Everything is plain HTTP on 127.0.0.1. Read the port from ~/.claude-device-manager/port instead of hard-coding 47823. If the file is missing, the app is closed and you can use devices freely.

How a hold works

These steps happen in this order. Your app is one more holder in the queue, next to Claude sessions.

1 · acquire

Ask for a kind

Phone, watch, tablet or any. Optionally Android or iOS, real or virtual. Or name one device.

2 · wait

Keep the line open

The reply streams QUEUED lines and a . every 5 s until you get a device.

3 · use

Talk to that serial only

Pass the granted serial to adb or the UDID to simctl. Call renew every 60 s.

4 · release

Hand it back

Release when done, and on crash or quit. The next holder gets it at once.

Example

A screen-mirror app that controls a phone

The app wants a real Android phone, mirrors it with scrcpy, and gives it back when the window closes. Pick a holder ID that stays the same across launches and starts with your app’s name, like scrcpy-vwr:main. The device list then shows who has the device.

# Find the server. No port file means the app is closed.
PORT=$(cat ~/.claude-device-manager/port) || exit 0
BASE="http://127.0.0.1:$PORT/cdm"
HOLDER="scrcpy-vwr:main"

# Wait up to 10 minutes for a real Android phone.
curl -sN -X POST "$BASE/acquire?holder=$HOLDER&category=phone&platform=android&virtual=false&timeoutSec=600" \
  | while read -r kind plat serial name; do
      case $kind in
        QUEUED)  echo "In line, position $plat" ;;
        GRANTED) echo "Got $name"; scrcpy -s "$serial"; break ;;
        TIMEOUT|BLOCKED|REMOVED) echo "No device: $kind"; break ;;
      esac
    done

# Always give it back.
curl -s -X POST "$BASE/release?holder=$HOLDER"
val port = File(System.getProperty("user.home"), ".claude-device-manager/port")
    .takeIf { it.exists() }?.readText()?.trim() ?: return runFreely()

    .POST(HttpRequest.BodyPublishers.noBody()).build()

val serial = http.send(req, HttpResponse.BodyHandlers.ofLines()).body()
    .map { it.split(' ', limit = 4) }
    .peek { if (it[0] == "QUEUED") ui.showQueue(it[1].toInt()) }
    .filter { it[0] in setOf("GRANTED", "TIMEOUT", "BLOCKED", "REMOVED") }

    .let { if (it[0] == "GRANTED") it[2] else null }

import pathlib, requests, atexit, subprocess

port_file = pathlib.Path.home() / ".claude-device-manager/port"
base = f"http://127.0.0.1:{port_file.read_text().strip()}/cdm"
holder = "scrcpy-vwr:main"
atexit.register(lambda: requests.post(f"{base}/release", params={"holder": holder}))

params = {"holder": holder, "category": "phone", "platform": "android",
          "virtual": "false", "timeoutSec": "600"}
with requests.post(f"{base}/acquire", params=params, stream=True) as r:
    for line in r.iter_lines(decode_unicode=True):
        kind, *rest = line.split(" ", 3)
        if kind == "QUEUED":  print("position", rest[0])
        if kind == "GRANTED": subprocess.run(["scrcpy", "-s", rest[1]]); break
        if kind in ("TIMEOUT", "BLOCKED", "REMOVED"): break

Endpoints

All under /cdm. Parameters go in the query string. Replies are plain text, one line per fact.

CallParametersWhat it does
GET /llms.txt—The agent brief below as plain text, with this server’s port filled in.
GET /cdm/ping—Replies cdm-ok. Use it to check the app is up.
POST /cdm/acquireholder*, category, platform, virtual, device, timeoutSec, cwdWaits for a matching device. Streams QUEUED lines and heartbeats, then one final line. Closing the connection leaves the queue.
POST /cdm/releaseholder*, platformGives back every device, or only one platform’s. Replies RELEASED or NONE.
GET /cdm/statusholder*One HOLDING line per device, then QUEUED n if waiting. NONE if neither.
GET /cdm/devices—Every device with platform, kind, category and who holds it, plus the queue. Feeds the list above.
GET /cdm/listholderThe same devices as plain text, one per line: serial, name, platform and kind, category, then free, yours, in use by …, offline or don't use. What cdm devices prints.
POST /cdm/renewholder*, platformResets the idle timer of the hold, or one platform’s with platform. Replies RENEWED or NONE. Call it every 60 s while in use.
GET /cdm/events—Server-sent events. Event devices carries the same JSON as /cdm/devices on every change.

* required. category: phone, watch, tablet, phone,watch or any. platform: android or ios. virtual: true for emulators and simulators, false for real hardware. device: one specific device, by adb serial, hardware serial, iOS UDID or exact name (use serial from /cdm/devices). You wait for that device only, and category defaults to any. An unknown, ambiguous or don’t-use device, or one the other parameters rule out, gets HTTP 400 with a one-line reason.

Reply lines from acquire

.
Heartbeat every 5 seconds. Ignore it.
QUEUED 2
You are second in line. Sent again when your place changes.
GRANTED android 39071FDJH00A2K Pixel 8 Pro
Platform, then the serial (or iOS UDID), then the device name, which may contain spaces.
TIMEOUT 1
Your wait ran out at that position. Call acquire again to keep your place.
BLOCKED
The user blocked this holder in the app. Stop asking.
REMOVED
The user took you out of the queue.

Playing nice

Use only the device you were given

Always pass -s <serial> or the UDID. Never run adb kill-server or simctl shutdown all.

Release on every exit path

Normal close, crash handler and shutdown hook. A forgotten hold blocks Claude until the idle timer runs out.

Keep one holder ID per window

Use yourapp:main, or yourapp:window-2 for a second device. The part after the colon names a sub-holder.

Expect the user to step in

The user can release your device, block you, or give it to someone else. Check /cdm/status before long jobs.

Idle release applies to you tooA device is released after 15 minutes without a device command (the time is set in Settings). The app only sees commands from Claude sessions, so call /cdm/renew every 60 seconds while you use the device.
For coding agents

Building an integration with Claude or another agent

If an agent is writing the integration for you, give it the brief below. It holds the whole contract in one block, so the agent doesn’t have to guess the wire format or skip the release path.

Paste

Copy the brief

Paste it into the agent’s chat, or into the project’s CLAUDE.md or AGENTS.md.

Fetch

Point it at the server

The agent can read GET /llms.txt. It returns this brief with the live port filled in.

Verify

Have it run the checks

The checklist below can be run against the live app. The agent should pass every check before it calls the work done.

Checks the agent should run

  • cdm app closed: the integration starts and works without a lock. No error and no retry loop.
  • Two copies of the integration, one device: the second shows QUEUED 1. It gets the device after the first one quits.
  • Kill the integration with kill -9 while holding a device. On next launch it releases the old hold before it acquires again.
  • Cancel while queued. /cdm/status for that holder then returns NONE.
  • Release the device from the CDM window. The integration notices within 60 s and stops using the device.
  • Every adb or simctl call in the diff names the device. Search the diff for adb without -s and for booted.
Agents testing on a device follow the same queueA Claude session that runs the integration still runs cdm acquire for its own testing first. The integration then queues behind that session. Give the integration a different category or use two devices, or the checks will deadlock.
